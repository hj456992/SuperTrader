# 管理员概要审核原型

范围依据：上级目录 README.md 与第13篇存储设计。已获授权，本目录只做静态演示，不接入生产。

## 实施与验证计划

使用 writing-plans 将本轮工作限定为三部分，直接在本会话执行，不委派、不提交：

1. `core.js` / `checks.cjs`：先定义确认、否决、原因补充、提问、历史冲突和幂等的行为测试；实现独立状态转换。确认绑定当前已展示的概要版本、内容摘要和完整概要范围。
2. `index.html` / `style.css` / `app.js`：侧栏展示全流程，内容区展示演示概要、来源占位和版本历史；聊天区保留管理员原话和待答问题。仅概要阶段可操作。
3. 运行 Node 语法和状态测试，浏览器检查交互及刷新恢复。验证结果与限制补在本文；不修改统筹所有的既有章节。

直接打开 `index.html` 即可，无构建、网络请求或外部依赖。浏览器不允许 file:// localStorage 时会提示无法保存，需在允许本地存储的浏览器打开或由统筹通过静态预览访问；不得显示虚假的保存成功。

## 已交付的演示交互

- 左侧全流程导航，当前概要审阅；确认后只停在待审子专家入口。后续阶段显示未实现且不能执行。
- 《金字塔原理》的概括性演示概要；无真实书籍读取、真实页码或引文，来源和覆盖均明确占位。
- 完整概要确认绑定展示对象、版本、内容标识与 `summary.full` 范围；审核记录使用 `approve/reject`。
- `phase=summary → specialists`，`build.status=active` 始终保持；生成状态与审核状态分别显示，概要通过不表示团队完成。
- “不通过”进入 `needs_reason`；“补充原因：……”保存原因并出新稿。最初 `reason=null` 的否决记录不被改写，带原因的记录另追加并关联当次原话与请求身份。
- “不通过：需要说明适用边界”创建新版本。改稿采用固定边界补充模板，管理员意见独立标注，不假称模型已理解或执行任意修改，也不假称其为原书观点。
- 问答、条件句、引用、标题等局部确认与含糊“可以”不批准。当前只有精确句式“确认概要 vN”可以批准；这种保守演示规则不是实际自然语言意图识别器。
- 完整历史、段落差异、生产进度与聊天焦点分离、旧版确认冲突、重复请求检查、原话保存及刷新恢复。
- 同一请求身份核对原话及对象/版本/摘要/范围；换快照不是重试。初次与重复提交的实际消息数可在检查脚本验证。
- localStorage 独立键 `ailiao.design.expert-summary.prototype.v1`；重置只覆盖这个键。记录损坏或保存失败会停止审核，不能假报成功。

## 建议点击顺序

1. 直接打开 `index.html`。点击“提问不推进”→发送，再用“解释后的‘可以’”→发送，观察概要仍待确认。
2. 点击“无原因否决”→发送，显示待补充原因。刷新页面，聊天和问题仍在。
3. 点击“补充原因”→发送，生成 v2；展开“本版变化与完整历史”，查看 v1 原文及两条审核记录。
4. 展开“演示检查与边界”，点击“提交旧版确认”，应显示版本冲突；点击“重试上一请求”，不会重复增加聊天或改稿。
5. 从下拉框查看 v1，观察生产进度仍在概要审阅；回到当前稿，点击“确认概要 v2”。只进入子专家未实现入口。
6. 点击“重置演示”，恢复初始概要 v1。可另试“条件不是确认”。

浏览器实测限制：电脑操作工具因 Browser URL policy 明确拒绝 `file://` 页面。未绕过该拒绝，未改用其他浏览器通道，也未启动或修改现有服务。因此尚未完成真实浏览器的视觉、响应式、键盘和 file:// localStorage 兼容性验收；不得把 Node 适配器的刷新重建检查称为真实浏览器刷新测试。

交付限制：纯静态交互原型，未接模型/数据库/Redis、权限体系、真实书籍或运行 state；没有异步生成任务，不验证取消、租约代次或迟到模型结果。多标签页只检测已经可见的存储变化，localStorage 无法提供原子事务或集群并发保证。`demo-…` 内容标识为演示校验值，不是生产 SHA-256。任意自然语言修改、专业准确性、整书覆盖及后续生产流程均未实现。

本轮只修改 `prototype/`；既有架构章节由统筹根据本记录更新。没有提交、推送、部署、新建任务或扩展委派。
