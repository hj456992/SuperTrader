# 管理员生产独立验收门槛

本轮授权为真实生产实现；此文件是先于实现固定的验收条件，不是通过记录。测试只在专用数据库的 `ep_qa_*` schema、临时原文目录和本机随机端口运行。测试模型仅在 `src/test`，不用旧原型 core 替代生产服务。

## 完整十二步

| 要求 | 可执行观察与失败条件 |
| --- | --- |
| 1 预学习及来源 | HTTP 创建返回后 PG 已有 build、草稿与任务；模型阻塞时也存在。学习成果保留实际 fixture 来源；全部生成后才入库视为失败。 |
| 2 展示全书概要 | snapshot 当前概要已封存、完整正文和来源可读，assistant presentation 对应同一修订；不直接跳到专家。 |
| 3 概要确认 | 对当前已展示完整概要明确确认后产生一条批准，推进且仍 active；生成成功不算批准。 |
| 4 否决/原因/修订 | 无原因产生未决问题；不能继续批准；补充真实原因生成新版本，旧拒绝记录不改写，新版 pending。 |
| 5–6 逐位子专家 | 各专家有职责、模型、工具、能力、边界、完整实际提示词、来源。逐位审核；名称/职责/修改方向认可不能批准完整专家。 |
| 7 兜底 | 专业专家后出现独立 fallback，未审核不能跳过；并非把最后一名 specialist 充当兜底。 |
| 8 主专家 | router 的完整提示词及路由职责可审，明确批准才能继续。 |
| 9 关键词 | 每名专业专家的路由关键词绑定真实专家身份，待审核持久保存，不在生成时当作已批准。 |
| 10 示例问答 | 书中依据与目标专家可追溯；L2 配置余弦严格 >0.90，生成及审批与用户侧执行分开。 |
| 11 主专家路由规则 | 生产配置包含 L1/L2 多专家命中交 L3、L1未中才L2、L2未中L3；不开发用户侧执行。 |
| 12 整体确认 | 必要成果、完整提示词、无未决澄清及当前依赖的具体快照展示后，管理员最终确认才能 completed；无需试聊启用充当前置。 |

## 负例与故障门槛

1. 条件、引用、询问、局部认可及闲聊不会批准整体。自由聊天允许模型解析，但程序复核版本、展示、范围和原始确认依据。
2. 相同请求身份同内容重试不重复消息/审批/生成；不同内容409。已处理成功后的原请求重试不因阶段变化失败。过期修订或内容摘要、跨构建对象均不能批准。
3. 请求和生成引用不能跨出所选版本；原文只读且按码点范围返回。拒绝原因不能修改原文。
4. 突然停止/重新启动服务，PG草稿、消息、审批和任务恢复；两个实例只允许当前owner/epoch提交。旧worker晚到不能覆盖新结果。
5. 暂停保留已保存成果且允许解释；继续恢复当前工作，取消不可复活；取消中的模型可故意忽略中断以检验提交屏障。
6. 已确认上游修改产生新版本并只使实际依赖失效；不相关专家/成果保持原版本与有效确认。失效必要成果不能整体完成。
7. Redis通知/缓存失败不丢已提交数据，PG事件仍能补读；已配置的共享额度服务失效不能放行新付费调用。
8. 模型失败/非法结构/越界引用不等于管理员否决；错误明确持久化，重试不得覆盖历史或假报完成。

## 证据分层

- 受控模型 + 真实 PG + 真实 HTTP：证明程序流程、校验、持久化与隔离，不证明模型理解质量。
- 真实模型隔离流程：另由统筹执行并记录供应商、固定样本、实际输出及质量审阅，不能由替身通过推定。
- 浏览器：另核对真实页面、完整提示词展示与刷新恢复，HTTP 测试不能代替渲染实测。
- PostgreSQL 两实例/租约与 Redis 故障：必须有可执行故障观察，不用设计文字或单进程锁推定。
