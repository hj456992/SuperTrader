## RQ-01 的最小必要引文与时间来源

1. `self.profile.summary`：「材料有限，且均为同一天的几条短句」；`self.profile.uncertainties[4]` 进一步写「三条材料均为同一天的短句，缺少时间跨度，无法评估重复一致性」。
2. `self.profile.facets[3].confidenceReason`：「三条材料指向一致，但集中在同一天、单一话题，稳定性未验证」。
3. 林舟 `profile.summary` 的来源歧义原句：「据用户描述之外无其他信息」；同一摘要已经明确「林舟在两条本人发言中描述了与散步有关的偏好」。

三条小禾材料的 `at` 分别为 `2026-09-24T12:59:15.042174Z`、`2026-09-24T12:59:15.935085Z`、`2026-09-24T12:59:19.680886Z`，都没有 `sourceKey`。这三个时间恰好在同一日，但它们是 smoke 连续录入时间；`5bfd899:src/main/java/dev/garden/RanchData.java:48` 的手动 `material` 构造明确执行 `m.put("at",now())`，不解析用户原文中的发言时间。

因此，**可以确认“同一天”缺乏原文或真实消息日期依据**。录入 `at` 是输入里唯一可见的精确日期，故高度符合模型把录入时间当发言日期的解释；没有模型内部过程证据，不声称能证明其内部推理路径。即使原话恰好曾于同日说出，这个样本也没有该依据，仍不能写成事实。

## 原范围内最小修正建议（交 TL 决定实施）

- 保留存储与内部排序需要的 `at`；在已有画像模型输入及聊天工具观察的材料副本中，不把手动材料的录入 `at` 当发言时间传递。可以移除该副本中的录入时间，并在现有提示明确：没有可靠消息时间或原文证据时，不得断言同一天、连续多日、近期反复等时间分布；只说“现有材料的时间跨度未知”。无需新增数据库字段、服务、时间提取器或身份系统。
- 同时检查初始材料和补查工具结果，避免模型从另一入口重新看到未解释的录入日期。真实来源的消息日期只有在语义可靠时才能用于发言时间判断；`sourceKey` 的存在本身不证明某个时间字段是发言日期。
- 现有指令内补齐来源称谓：them 原文称“本人发言”，person-notes 才称“据用户描述”；用户提供文件不等于文件中每条发言都是用户转述。保留直接/推断既有标签规则，explicit 只复述直接表达。
- 在现有确定性测试中检查人工录入时间不会进入模型可误读的发言时间位置，覆盖初始输入与工具观察；用同一虚构夹具补一次真实模型复验，确认“同一天”不再出现，来源措辞和 explicit 条目仍准确。该复验由 TL 安排，本产品审阅未自行触发。
