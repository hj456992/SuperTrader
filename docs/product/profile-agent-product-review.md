## 已确认问题

### PRD-RV-01 · P2 · 错误/中断提示不能关闭

- 对应：A17/A20/A22，既有错误提示关闭能力及新中断状态。
- 集成位置：`web/src/ranch-view.js:46` 为 `error/interrupted` 渲染「关闭提示」且仍使用 `cancel` action；`web/src/ranch-ui.js:114–120` 对该操作调用取消 API 后重新读取状态；`src/main/java/dev/garden/RanchAnalyzer.java:103` 对非 `running/cancelling` 直接返回。
- 触发：画像失败或重启后显示中断，用户点击「关闭提示」。
- 实际：取消接口不改变终态，刷新后提示和按钮原样显示。人物已删除时也无法通过现有按钮关闭遗留错误。
- 最小修复方向：由 TL 协调现有前端实现按任务 ID 关闭当前提示（或沿用一致的既有终态关闭约定）；不要把完成状态改成取消成功，不放松定向取消、保存屏障或新任务隔离，不需要新接口。
- 复验：error/interrupted 的按钮确实关闭当前提示；后续新 run 的提示仍出现，旧关闭动作不得吞掉新 run 的状态。

### PRD-RV-02 · P3 · 首次取消暗示存在旧画像

- 对应：A14/A15 及最小取消文案。
- 集成位置：`web/src/ranch-view.js:43` 的 `cancelled` 文案无条件为「任务已停止，已保存的画像仍可查看」。
- 触发：人物没有任何已保存画像，首次生成被取消。
- 实际：页面同时显示空画像和上述已保存提示；文案未明确「本次结果未保存」。
- 最小修复：采用基线「任务已取消，未保存本次结果」；如保留旧画像说明，仅在确有旧画像时追加。不得因文案修复新增恢复、历史或自动重试功能。
- 复验：无旧画像与有旧画像各一例；完成先于取消的任务仍按 done 显示，不能误报未保存。
